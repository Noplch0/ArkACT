# ArkACT

**《明日方舟》PC 端「卫戍协议」专用伤害统计插件。**

基于 [ArkFramework](https://github.com/wuyu8512/ArkFramework)，以紧凑浮层展示玩家与干员伤害，并将整局和各轮数据保存为多工作表 XLSX 报表。

- 当前工作区源码版本：**1.2.0**
- 当前公开 Latest：**1.2.0**
- 运行平台：**Windows x64**
- 适用模式：**仅卫戍协议**
- 下载地址：[GitHub Releases](https://github.com/Noplch0/ArkACT/releases)

> **使用提示**：本项目是非官方第三方工具，与游戏官方无关。第三方插件可能违反游戏用户协议，请在了解风险后自行决定是否使用。

## 功能一览

- **玩家与干员两级统计**：按实际伤害排序，展示伤害、DPS 和占比；展开玩家后可查看各干员的计算伤害、治疗量、HPS 与元素损伤。
- **1–4 人联机统计**：显示本机实际模拟并确认归属的玩家，不抓包或发送网络请求。
- **对局信息**　主界面显示本局种子和隐藏 Boss 的名称。
- **商店记牌器**：按干员或盟约统计货架出现次数，并按玩家查看观测到的获得、推定商店获得、推定卖出和当前持有数量。
- **战斗与协防分开**：主战斗和协防分别累计伤害与时间，互不混入对方的 DPS。
- **整局与逐轮查看**：可切换整局累计或指定轮次，也可翻查已采集的历史轮次。
- **更合理的 DPS 计时**：准备、结算和自己打完后的等待时间不计入个人主战时间；玩家退出、掉线或淘汰后停止计时并保留已有数据。
- **附加伤害归属**：在证据充分时，将持续伤害（DoT）、召唤物、陷阱和弹射物伤害归回所属干员与玩家。
- **局外回顾与报表**：离开对局后仍可查看刚结束的一局；导出单个 XLSX 文件，内含整局累计和每轮工作表。

## 安装前准备

你需要先准备：

1. 《明日方舟》PC 客户端；
2. 与当前游戏及本插件兼容的 **ArkFramework**；
3. 该 ArkFramework 版本配套的 **ArkImGui**。

本插件**不需要其他前置插件**，不依赖 `damage_meter.dll`、`buff_capture.dll` 或 buff 服务。不要同时启用旧版 `operator_stats`，以免重复统计。

发布包不包含 ArkFramework、ArkImGui 或独立注入器。请按照 ArkFramework 自身的说明安装和启动框架。

> **版本说明**：截至 2026-11-24，公开 Latest 为 v1.2.0，包含对局种子/Boss 信息、商店记牌器及相应修复。

## 安装与更新

1. 从 [Releases](https://github.com/Noplch0/ArkACT/releases) 下载已公开发布版本的 `ArkACT-v<版本>-windows-x64.zip`；同名 `.sha256` 文件可用于校验下载完整性。
2. 将压缩包解压到一个临时目录。
3. 把压缩包内的 `plugins/stronghold_stats.dll` 复制到：

   ```text
   <ArkFramework目录>\plugins\stronghold_stats.dll
   ```

4. 如果旧版本已被框架加载，请先通过框架正常卸载插件，或在框架未运行时替换文件；不要覆盖正在使用的 DLL。
5. 通过 ArkFramework 正常启动游戏，按 **Insert** 打开或关闭框架浮层（如修改过按键，以框架设置为准）。进入卫戍协议后，插件加载成功且已有统计数据时会显示所加载版本的版本号。

> **整个 ArkFramework 和本插件都应放在游戏安装目录之外。** 游戏目录可能清理非原版 DLL，不要把插件复制进游戏本体目录。

可选：在下载目录用 PowerShell 计算 ZIP 的 SHA256，并与 `.sha256` 文件中的值核对。

```powershell
Get-FileHash .\ArkACT-v1.2.0-windows-x64.zip -Algorithm SHA256
```

运行插件不需要安装 Python、Visual Studio 或报表生成工具。

## 界面怎么用

| 控件 | 作用 |
| --- | --- |
| **范围：整局 / 本轮** | 在整局累计与所选轮次之间切换。 |
| **阶段：战斗 / 协防** | 在主战斗与协防统计之间切换；两种阶段分别计时。 |
| **上一轮 / 下一轮** | 查看已经采集的轮次，不会修改当前游戏进度。 |
| **轮次下拉列表** | 直接选择轮次；选择最新轮后会继续跟随新轮次。 |
| **玩家行** | 展开或收起该玩家的干员明细。 |
| **清零** | 经确认后清空本场插件统计。需要保留数据时，请先导出工作簿。 |
| **导出整局工作簿** | 将当前已采集的整局与各轮数据导出为 XLSX。 |
| **导出诊断** | 导出适配与采集状态日志，供排查问题使用。 |
| **伤害统计 / 记牌器** | 切换伤害统计与商店记录；新对局默认进入伤害统计。 |
| **记牌器内视图** | 切换出现频率或玩家干员。出现频率可按干员或盟约查看，选「全体」显示合计和各玩家次数，选 P1–P4 中的一人时只按该玩家商店的次数显示和排序。 |
| **采集提示 / 导出结果** | 查看数据不完整、版本不兼容、导出结果等提示。 |

界面顶部的“整局-战斗”“本轮-协防”等文字表示当前正在查看的组合。表格较长时可在明细区域滚动，表头会保持固定。

主界面显示本局种子和从客户端敌人图鉴查到的隐藏 Boss 名称。种子和 Boss 查找键来自只读游戏对象或同步快照。

插件加载后、尚未进入卫戍协议时会先显示“插件已加载/等待进入卫戍协议”的等待面板；运行时和输入就绪后提示可以开始对局。只有已有历史对局或进入首个 Session 后才显示统计表。

离开卫戍协议后，插件保留刚结束一局的只读数据；进入下一局时才替换这份内存缓存。插件重载或游戏进程关闭后，未导出的内存数据不能恢复，但已经生成的 XLSX 文件仍然保留。

## 如何理解统计数据

### 对局信息与商店记牌器

- **种子与 Boss**　插件用 `hiddenBossId` 查本局 Boss 配置和敌人图鉴。读到编号但查不到名称时显示「名称未读取」，缺少编号时显示「不可用」。
- **商店出现频率**　记牌器独立记录本机货架，队友货架以本机收到的准备状态为准。同一刷新序号 `refreshSeq` 内重复观察到同槽位的同一干员只记一次。前后均冻结且留在同一玩家同一槽位的干员，跨刷新或保留到下一回合时只计首次，干员和盟约频率都遵循这条规则。同一干员占多个槽位时分别计次，并计入可识别的各基础盟约。缺少序号时按槽位内容变化计数，并显示数据不完整。结果相同的刷新或两次采样间的中间货架可能漏记。
- **名称显示**　出现频率和玩家干员表使用客户端配置中的干员名和盟约名。读取不到时显示「干员名称未读取」或「盟约名称未读取」。同一条目后续读到名称时会更新显示。
- **玩家干员表**：获得数量合并 round analytics 的获得记录和持有数增量，避免重复相加；首次观察到的既有阵容只作为当前持有基线。持有减少显示为“推定卖出”，因为客户端快照不能证明减少一定来自出售。商店来源仅在获得记录与同一刷新序号下货架槽位消失相匹配时标为“其中商店”，其余来源不猜测。
- **数量口径**：获得、持有和推定卖出按实际干员实例计数，不把高星干员折算成基础副本数。玩家槽位按 P1–P4 显示；如果队友准备状态也在本机可读快照中，则一并统计。
- **完整性与边界**：刷新序号缺口、观察队列溢出或关键字段缺失时显示数据不完整。记录只保存在插件内存中，新对局清空；不抓包、不解密、不修改协议/服务器数据，也不从种子推演未观察到的商店。

### 实际伤害与占比

- 玩家排名的主口径是敌人实际扣除的 HP，即 `abs(realDelta)`，不是计算伤害。
- 计算伤害、治疗量、HPS 和元素损伤作为补充指标显示，不替代实际伤害排名。
- 伤害占比以当前所选“范围 + 阶段”的已采集实际伤害总量为分母，包括单独列出的未归属伤害。
- 同一玩家的同种干员重复实例会合并并显示实例数；不同玩家的同名干员不会合并。

### DPS 与计时

- 每位玩家使用自己的有效战斗时间计算 DPS/HPS，不使用全房间统一的墙钟时间。
- 自己完成主战后，等待其他玩家的时间不会继续拉低自己的 DPS；尚未完成的玩家仍各自计时。
- 协防使用独立的伤害与时间统计，不会并入主战 DPS。
- 玩家明确退出、掉线或淘汰后，已有数据保留，计时停止。

### DoT、召唤物与未归属伤害

持续伤害不会单独列成一行；能够确认宿主时，会与召唤物、陷阱和弹射物伤害一起计入所属干员及玩家。

无法完整确认来源时，插件不会猜测归属：

- **未归属附加伤害**：只能确认所属玩家、不能确认具体干员时，列在该玩家下。
- **无来源附加伤害**：能确认是实际敌人扣血、但没有可靠来源时单独列出。它可能包含无法区分的环境伤害，不能视为某位玩家的输出。
- 完全脱离当前采集链的直接改血，或缺少必要目标/宿主证据的效果，仍可能无法统计。具体盟约与干员组合需要实机验证。

### “全房间 / 仅本机 / 部分采集”是什么意思

插件只能统计**本机实际模拟**的战斗数据，不会从服务器或其他玩家的电脑同步伤害。

| 范围标识 | 含义 |
| --- | --- |
| **全房间** | 已确认的本地模拟玩家覆盖全部在线房间玩家。 |
| **仅本机** | 当前只确认采集到自己，常见于游戏不模拟队友的情况。 |
| **部分采集** | 只确认了部分在线玩家，队友数据并不完整。 |
| **检测中** | 尚无足够证据判断覆盖范围。 |

未采集到的队友不会被伪造成“0 伤害”。画质可能影响游戏是否在本机模拟队友，但插件以运行时实际玩家集合为准，而不是仅按画质档位猜测。

## XLSX 报表

报表保存在：

```text
<ArkFramework目录>\exports
```

- **完整对局**：以对局结束时的本机本地时间命名，精确到分钟，例如 `2026-11-14 19-30.xlsx`。Windows 文件名不能包含冒号，因此时间写作 `19-30`；同分钟的多局会自动添加 `(2)` 等后缀。
- **对局中手动导出**：使用 `进行中-<pid>-<session>.xlsx`，完整结束报表保存成功后会清理对应的进行中文件。
- **手动清零或未结束时卸载**：使用 `中断-<pid>-<session>.xlsx`，不会把中断时间冒充正常结束时间。

每个工作簿包含 `整局累计`、`第01轮`、`第02轮` 等工作表，每张表分别列出主战与协防数据。报表包含玩家槽位、显示昵称、干员、实例数、实际伤害、有效战斗时间、DPS、伤害占比、计算伤害、治疗量、HPS 和元素损伤。

- 伤害占比使用真正的百分比格式，可以直接在表格软件中计算和筛选。
- 玩家状态附在昵称后，例如“玩家A(在线)”或“玩家B(中途退出)”。
- 不导出原始 UID、昵称编号、内部干员 ID、统计范围或独立状态列。
- 生成工作簿不需要安装 Excel 或 Python；查看文件时可使用支持 XLSX 的表格软件。

## 常见问题与排障

### 面板没有出现

本插件只在卫戍协议中采集和显示。尚未采集过数据时，其他关卡不会出现统计面板。进入卫戍协议后仍无面板，请检查框架是否成功加载 `stronghold_stats.dll`，以及 ArkImGui 是否与框架匹配。

插件启动后可能需要等待游戏运行时就绪。若超过等待时间仍提示连接失败，请记录界面错误并导出诊断。

### 能显示昵称，但伤害一直是 0

先查看“采集提示 / 导出结果”中的警告。若对局中确实已经造成伤害而数值始终不变，请尽量**在问题发生的对局内**点击“导出诊断”，并保存对应日志。局外日志可用于查看保留快照，但不能替代问题发生时的完整状态。

### 联机时只能看到自己

查看顶部范围标识。“仅本机”表示当前只确认本机模拟了自己，并不表示队友实际没有造成伤害。插件无法读取未在本机模拟的队友战斗，也不会用零值补全队友。

### 提示“游戏版本结构不兼容”

游戏更新可能改变插件依赖的数据结构。此时插件会停止采集，而不是猜测字段或继续生成不可靠数据。请提供界面错误和自动生成的诊断日志，等待适配新版本；不要尝试用旧版日志或偏移强行绕过检查。

### 部分盟约、干员或召唤物伤害缺失

先切换到正确的轮次和“战斗 / 协防”阶段，再检查是否存在“未归属”行及采集警告。若确认仍有遗漏，请在问题发生的对局内导出诊断，并记录干员、盟约、轮次和伤害表现，以便定位来源链。

### 工作簿导出失败

检查 ArkFramework 目录是否可写、磁盘空间是否充足，并关闭可能占用同名文件的表格软件后重试。界面会显示写入结果或失败原因；失败时会保留待写快照供重试，但进程关闭后无法保证仍能恢复未写出的数据。

### Excel 打开报表时提示修复“工作簿属性”

1.0.1 起修复了导出文件中的兼容性问题，1.2.0 继续包含该修复。更新插件后新导出的报表可正常打开。旧文件不会自动改写，可以在 Excel 完成修复后另存为新文件；如果插件仍保留该局数据，也可以重新导出。热重载会清空内存统计，更新前请先保存需要保留的报表。

### 重载插件后历史轮次消失

插件的当前对局缓存只保存在内存中，热重载会重新建立缓存，不能补回重载前已经发生但未保留的伤害。已经导出的工作簿不受影响；进行中重载后只能继续采集后续事件。

## 诊断与反馈

诊断日志位于：

```text
<ArkFramework目录>\diagnostics\stronghold-schema-<游戏进程PID>.log
```

日志包含游戏结构、采集状态和保留的局内/战斗快照，不写入玩家原始 UID、昵称编号或昵称值。分享任何日志或报表前，仍建议自行检查内容；XLSX 报表按设计会保留显示昵称。

反馈问题时，请附上：

- 插件版本与当前游戏版本；
- 问题发生时是单人还是联机，以及界面显示的统计范围；
- 对应轮次、战斗/协防阶段和可复现步骤；
- 尽量在问题发生的对局内导出的诊断日志。

可在 [GitHub Issues](https://github.com/Noplch0/ArkACT/issues) 提交问题。

## 卸载

先通过 ArkFramework 正常卸载插件，或在框架未运行时移除 `plugins/stronghold_stats.dll`。已经生成的报表和诊断不会因此自动删除；如不再需要，可自行检查后再处理对应文件。

## 只读与隐私边界

本插件没有修改伤害、血量、技能、资源、关卡、结算、存档或服务器数据的功能，也不包含网络上报、游戏命令执行或独立注入功能。

为读取已结算事件，ArkFramework 会安装原生 Hook；运行时还会使用对象保活和浮层输入保护。这些属于实现机制，因此不应理解为“整个游戏进程完全没有任何内存改动”。插件自身只将采集结果保存到本地统计模型、报表和诊断中。
